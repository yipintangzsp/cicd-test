### 候选项 #3：[待填充 - 示例：journald 日志大小限制]

| 属性 | 内容 |
|------|------|
| **建议动作** | 在 `/etc/systemd/journald.conf` 追加 `SystemMaxUse=500M`，然后 `systemctl restart systemd-journald` |
| **触发条件** | /var/log 使用率 ≥ 80% 且 journald 占用较大 |
| **预期收益** | 防止日志无限增长、磁盘爆满影响服务 |
| **风险等级** | 🟡 中低（会丢弃旧日志，重启 journald 有 <1s 日志中断） |
| **回滚方式** | 删除添加的配置行，`systemctl restart systemd-journald` |
| **是否推荐** | 视磁盘实际情况决定 |

## 明确不做的优化项

| 候选动作 | 不做原因 |
|----------|----------|
| 重启整机 | 违反约束，且所有 enable 操作均不需要重启生效 |
| 修改 vm.swappiness | 无充分 swap 抖动证据 |
| 修改 fs.file-max | 无 file-nr exhausted 证据 |
| 批量 kill 进程 | 无法识别业务高负载 vs 异常循环 |
| docker image prune -a | 可能删除仍需使用的镜像 |
| 升级内核/系统 | 违反绝对约束 |
| 修改数据库参数 | 无专项性能瓶颈证据 |
| 禁用未知服务 | 无法确认是否为平台依赖 |
